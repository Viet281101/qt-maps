# Unit 01b Vector Feasibility Evidence

## Status

Unit 01b is **partially complete at the pre-download approval gate**. The installed Qt 5.13.2 `mapboxgl` plugin has rendered a fully local synthetic MVT mechanics fixture with local style, glyph, and sprite resources, and the camera probe has retained requested bearing and tilt values. This is not the required real Hanoi dataset proof or the official three-run dense-urban benchmark.

No package, source dataset, font pack, style repository, Planetiler artifact, or MapLibre source was downloaded or installed during this work.

## Synthetic mechanics proof

The fixture is generated by `tools/generate_vector_fixture.py` with Python's standard library. It creates 100 small synthetic MVT files at zooms 12 through 15, a style, one project-owned sprite, and a deliberately limited project-owned glyph range. Hanoi coordinates are used only for XYZ addressing; the geometry is not geographic data.

Commands:

```bash
make vector-fixture
make serve-vector-fixture
make run-mapboxgl-probe
```

Observed on the Dell Latitude 5480 reference laptop:

- Qt 5.13.2 selected the user-provided loopback style and reported `mapReady=true`, error 0, and an empty error string.
- Mesa identified Intel HD Graphics 520. The plugin repeated its existing warning that threaded rendering is not optimal.
- The rendered frame visibly contained synthetic fill geometry, line geometry, the local sprite, and the `HANOI` label. The orange banner explicitly identified the fixture as synthetic and not real map data.
- The loopback request log returned HTTP 200 for `style.json`, `sprite.json`, `sprite.png`, `fonts/QtMapsSans/0-255.pbf`, and MVT files at zooms 12 and 13. No external runtime request was observed.
- Requested/observed camera values matched at bearing 45 degrees and tilt 30 degrees, then bearing 315 degrees and tilt 45 degrees. The plugin reported a tilt range of 0 through 60 degrees. Reset requests 0 degrees bearing and tilt.
- A screenshot was inspected at `/tmp/qtmaps-vector-probe-label.png`; it remains outside Git as run evidence.

## MapLibre Native estimate

The exact comparison candidate is `maplibre-native-qt` v3.0.0, tag object `4bc269e45c4fb384dae1e265a7233afef795ce92`. Its source archive is 201,386,043 bytes. The core is BSD-2-Clause; QML bindings are available under GPL-2.0, GPL-3.0, or LGPL-3.0, and examples are MIT.

The upstream v3.0.0 documentation states that Qt 5.15 is fully supported on desktop while Qt 5.6 through 5.14 support widgets but not Qt Location. The current main branch no longer supports Qt 5. The v3.0.0 build also requires C++17, while QtMaps currently uses C++14. There is no Qt 5.13 binary artifact.

Therefore a Qt 5.13 QML/QtLocation integration is a high-patch-burden path, not a drop-in replacement. A cautious planning envelope is 3 to 7 developer days plus several GiB of temporary source/build storage, followed by camera, offline-resource, lifecycle, and performance revalidation. Build duration and installed footprint are not measured because no source download or build was approved. Do not begin this build unless the installed plugin fails the real-data correctness, camera, stability, or owner-approved performance criteria.
